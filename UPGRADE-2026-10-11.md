# Home-lab upgrade, 11 October 2026

The deployment uses current stable releases, with explicit versions where a major update needs a migration. An image tag identifies what to pull. Running containers keep their existing image until Compose recreates them, even when the tag is `latest`.

## Nextcloud Mail fix retained

## Ethernet bottleneck

The home server's `enp8s0` link negotiated 10 Mbps full duplex. Auto-negotiation is enabled. The adapter supports and advertises 100 Mbps, while its link partner advertises only 10 Mbps. This caps total network transfers near 1 MB/s. The NIC driver is `r8169`. The link settings were read without changing them. Check the Ethernet cable and router port to recover the adapter's supported speed.

## Backups and rollback

Private backups live at `/home/taf/home-lab-backups/upgrade-20261011` on the home server and `/home/deployer/home-lab-backups/upgrade-20261011` on the VPS. They include the original container specifications, Compose files, database dumps, and application data. Those specifications and dumps contain credentials. Keep the directories private and outside Git.

Original running images have `home-lab-rollback/<container-name>:20261011` tags. Restore the corresponding pre-upgrade Compose file and application backup before starting an old application image. Database migrations can make new data incompatible with older binaries.

For PostgreSQL rollback, stop Forgejo and its runners, restore the old Compose file with PostgreSQL 16 and `/mnt/hdd01/forgejo/postgres`, and restore Forgejo's matching backup before starting the stack. Do not mount PostgreSQL 18 data into PostgreSQL 16.

Homarr's old `configs`, `data`, and `icons` directories remain for rollback. Its intermediate migrated database and encrypted legacy export also have private backups. A rollback needs the old image and old mounts together.

The upgrade retained rollback images, old database directories, and stopped migration containers. No image or volume pruning ran.
